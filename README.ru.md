# Метод «надувного шарика» (МНШ)

*задачи оптимального распределения плана производства* — задачи Канторовича о
распределении ассортимента / загрузке оборудования — и её нелинейного

## Постановка задачи

Имеется `m` предприятий (агрегатов / станков) `I = {1..m}`, на которых нужно
выпускать `n` изделий `J = {1..n}` в заданном ассортименте. Предприятие `i`
выпускает изделие `j` с производительностью `a[i][j]` (выпуск в единицу времени;
`0` ⇒ выпуск невозможен) и располагает ресурсом времени работы `z[i]`. Один
полный *ассортиментный набор* требует `b0[j]` единиц изделия `j`. Требуется
выбрать времена работы `x[i][j]`, максимизируя число полных наборов `mu`:

```
максимизировать  mu
при условиях     sum_i a[i][j] * x[i][j]  >=  b0[j] * mu     для каждого изделия j     (2)
                 sum_j x[i][j]            <=  z[i]           для каждого предприятия i (3)
                 x[i][j] >= 0                                                          (4)
```

### Идея «надувного шарика»

`mu` играет роль давления воздуха. «Надувание» `mu` расширяет поверхность
требований `b0[j]·mu` до тех пор, пока шарик не упрётся в стенки ресурсов
(ограничение 3). Наибольшее `mu`, при котором ещё существует допустимое
решение, и есть оптимум `mu*`. **Обобщённый** метод после этого продолжает
«выпячивать» *отдельные* критерии в оставшееся свободное пространство (см. ниже).

## Как работает метод

### Внешний цикл — надувание (`balloon/solver.py`)

Итеративный поиск `mu*` (формулы 9, 10, 26–31): старт от граничной оценки
`mu_gr/10`, рост, пока решение допустимо (`alpha = 0.1·mu/10^k`, формула 30), и
дихотомический шаг назад при «перелёте» (`alpha = -|Δmu|/2`, формула 31), пока
шаг не станет меньше `eps` (формула 9). Текущее значение удерживается внутри
интервала «допустимо / недопустимо», что гарантирует сходимость к `mu*`.

### Внутренний оракул — закрепление классов оценок + ветви и границы (`balloon/feasibility.py`)

Для фиксированного вектора требований определяет, существует ли допустимое
решение, и строит его. Оценки `s[i][j] = a[i][j]·d[i][j]` (формула 11)
показывают, сколько изделия `j` ещё может выпустить предприятие `i`. Они
классифицируются и *закрепляются* («закрепление оценок»):

| Класс | Определение (статья) | Смысл | Действие |
|-------|----------------------|-------|----------|
| **А** | единственная положительная оценка в **столбце** (опр. 1) | изделие может делать только одно предприятие | принудительное закрепление (ф. 15) |
| **В** | единственная положительная оценка в **строке** (опр. 2) | предприятие может делать только одно изделие | принудительное закрепление (ф. 16) |
| **С** | строгий максимум в столбце (опр. 3) | лучшее предприятие для изделия — идея *максимального элемента* | ветвление (ф. 22–25) |
| **D** | глобальный максимум оценки (опр. 4) | жадный максимальный элемент | ветвление (ф. 22–25) |

Классы А и В — детерминированные, заведомо верные упрощения. Когда остаются
только выборы С/D, решатель **ветвится** по наиболее «напряжённому» изделию,
перебирая его поставщиков в порядке максимального элемента, с отсечением ветвей
по необходимой оценке `P` (ф. 17) и по оценке отдельного изделия `Q` (ф. 18).

Закрепление `(k, l)` отдаёт время предприятия `k` изделию `l`: если `k`
покрывает остаток спроса — тратит ровно столько, сколько нужно, и оставляет
остаток времени; иначе отдаёт всё своё время, а недостаток покрывают другие.

### Обобщённый / нелинейный «надувной шарик» (`balloon/nonlinear.py`)

После равномерного оптимума `mu*` оставшиеся ресурсы используются за счёт
надувания каждого критерия по его собственной монотонно неубывающей функции
*желаемого уровня* `b[j] = f_j(b0[j], mu, t)` (формула 8, рис. 1–3 статьи 2019 г.)
— по кругу, с повторной проверкой полной допустимости, так что уже выданные
критерии не нарушаются. Результат — точка на границе Парето; потолки и порядок
задают многокритериальные предпочтения.

## Точность: точно там, где это важно

Метод закрепления классов **комбинаторен и точно соответствует статье** — а в
статье отмечено, что его эффективность повышается на **слабозаполненных
матрицах**. Сравнение с точным оптимумом ЛП на случайных задачах:

| плотность матрицы | доля точных совпадений | средн. отклонение | макс. отклонение |
|------------------:|-----------------------:|------------------:|-----------------:|
| 0.2               | 100 %                  | 0.000             | 0.000            |
| 0.3               | 100 %                  | 0.000             | 0.000            |
| 0.4               | 97 %                   | 0.0005            | 0.034            |
| 0.5               | 93 %                   | 0.0005            | 0.016            |
| 1.0 (плотная)     | 46 %                   | 0.0043            | 0.032            |

Итак, на **слабозаполненных** задачах — это и есть целевая область метода, и
именно такую форму имеют реальные производственные планы, как пример 20×16 из
статьи, — он достигает точного оптимума. На плотных матрицах это быстрый
эвристический метод и всегда корректная **нижняя оценка** (он никогда не
завышает `mu*`). Для гарантированного оптимума на *любой* задаче подключите
точный оракул:

```python
from balloon import BalloonSolver, LPOracle
res = BalloonSolver(p, oracle=LPOracle(p)).solve()   # точно при любой плотности
```

## Использование

```python
from balloon import Problem, BalloonSolver, solve_generalized

p = Problem.from_lists(
    a=[[2.0, 1.0, 0.0],
       [1.0, 2.0, 1.0],
       [0.0, 1.0, 3.0]],
    z=[1.0, 1.0, 1.0],
    b0=[1.0, 1.0, 1.0],
)

res = BalloonSolver(p, eps=1e-5).solve()
print(res.mu)                      # оптимальное число ассортиментных наборов
print(res.allocation.x)            # матрица распределения времени x[i][j]
print(res.allocation.slack_time)   # неиспользованное время по предприятиям

gen = solve_generalized(p)         # равномерный mu* + надувание по критериям
print(gen.demand)                  # надутые уровни требований b[j]
```

## Структура проекта

```
balloon/
  problem.py      модели Problem и Allocation, проверка ограничений
  feasibility.py  закрепление классов (А/В/С/D) + оракул допустимости (ветви и границы)
  solver.py       внешний поиск mu* методом надувания  (ф. 9,10,26-31)
  nonlinear.py    обобщённое надувание по критериям (нелинейное)  (статья 2019 г.)
  exact.py        эталон на ЛП (scipy): точный оптимум, LPOracle (контрольное решение)
examples/
  nelidovo_1977.py   пример 20x16 из статьи  (mu = 1.08)
  sample_problem.json
mib_tests/         набор тестов (запуск: python -m mib_tests.run_all)
run.py             запуск из командной строки
```

## Требования

* Python ≥ 3.9, **numpy** (для самого метода).
* **scipy** — только для точного эталона на ЛП (`balloon.exact`) и для тестов.

## Тесты

```bash
python -m mib_tests.run_all
```

Набор тестов сверяет внутренний оракул с независимым оракулом допустимости на
ЛП, подтверждает, что надувание достигает оптимума ЛП на слабозаполненных
задачах (и даёт корректную нижнюю оценку в остальных случаях), воспроизводит
указанное в статье `mu = 1.08` и проверяет, что обобщённое надувание остаётся
допустимым и доходит до границы ресурсов.
